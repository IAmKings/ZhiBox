# 生成《SAG Android MVP 开发实施计划 v1.0》文档

## 执行动作
创建 `docs/SAG_Android_MVP_Implementation_Plan_v1.0.md`（中文，与前两份 PRD 和调查报告同目录、同风格、交叉引用），作为 Phase 0/Phase 1 开发的任务分解凭证。不创建工程代码。

## 文档结构与核心内容

### 文档头
- 锚定四份既有文档；版本锚点三件套：SAG main commit `56f073c`、`zleap-sag==0.14.0`、wheel SHA-256 `c58d12f1...`
- 团队假设：1 名熟练 Android 工程师；工期总计 22 个工作日（Phase 0 = 7 天，Phase 1 = 15 天），与调查报告修正值一致

### 1. 目标与范围
- MVP = 离线个人知识搜索（模式 A）：TXT/MD 导入 → 分块 → 端侧 embedding → SQLite+精确扫描检索 → 原文证据回溯，全程飞行模式可用
- 非目标：事件/实体关系扩展（Phase 2）、生成式回答（Phase 3）、PDF/OCR、多模态、云同步

### 2. 技术决策基线（已定，不再讨论）
Kotlin+Compose / Room+SQLite（框架 SQLite + FTS4 起步）/ 精确余弦扫描（ANN 推迟，见附录 B）/ EmbeddingProvider+VectorIndex 抽象（接口按 PRD §4.1）/ Embedding 双路径待 R1 判定：Universal Embedder+EGemma2 或 Text Embedder+EGemma v1 / CPU(XNNPack) 默认、GPU 仅实验 / minSdk 24、arm64-v8a 优先 / 向量 768d f32 起步，256d(MRL) 留作评测后决策 / SQLite 为 source of truth，索引皆为可重建派生工件

### 3. Phase 0 技术验证（D1–D7 逐日任务）
- **D1**：工程初始化（minSdk 24/targetSdk 36/arm64）；从已解包的 zleap-sag 0.14.0 wheel 提取参考素材入库（清单见第 9 节）；建立 `docs/UPSTREAM_VERSIONS.md` 记录锚点
- **D2**：以官方 mediapipe-samples `universal_embedder/android` 为起点跑通 demo：440M 模型下载、embedText 冒烟、冷启动/热推理/RAM 记录（高、中端机各一）
- **D3 Spike-1（R1 任务模板）**：50 条中英文样本；桌面端 HF Sentence Transformers（正确 prompt）生成参考向量 JSON；端侧三种方式（原文 / 手工 `title: none | text: ` 前缀 / SearchQuery 前缀）与参考向量算余弦。判定：任一 ≥0.99 → 锁定该方式；全部失败 → 基线回退 Text Embedder+EGemma v1，记录 ADR
- **D3–4 Spike-2（R2 模型资产）**：确认 270M text-only `.litertlm` 是否存在；不存在则接受 440M+按需加载；同步盘点 Text Embedder 基线模型尺寸；产出模型分发方案结论（应用内下载器 + SHA-256 校验，MVP 不打包 assets）
- **D4 Spike-3（R3 中文分词）**：三方案各 50 条中文关键词原型对照——FTS4 原样（基线）/ bigram 预分词 / 分词器预分词；用小型中文语料测命中率与误报；选定方案 + 决策记录；自带 SQLite 的统一决策推迟到 ANN 阶段（附录 B 路径）
- **D4–5 Spike-4（精确扫描基准）**：1k/5k/10k × 768d（真实+随机混合）；三种实现对照：SQLite BLOB 逐行 / 预载 FloatArray / mmap 平铺文件；记录冷/热 p95、RAM；对照门槛（1k ≤150ms、10k ≤800ms）；选出 Phase 1 实现方案
- **D5–7**：`docs/PHASE0_REPORT.md` 判定门汇总：R1/R2/R3 结论、基线模型锁定、扫描实现选型、设备矩阵初测数据；go/no-go 进入 Phase 1（R1 失败不阻断，仅切换 W2 provider 实现对象）

### 4. Phase 1 离线搜索 MVP（W1–W3 逐周任务）
**W1 数据层与导入管线**
- Room schema：PRD §4.2 十张表 + 修订——`chunk_embedding` 增加 `role` 列对齐六向量角色协议（MVP 仅用 content，schema 预留）、`embedding_meta` 增加任务模板策略字段；`schema_migrations` 由 Room Migration 承担
- DocumentParser(TXT/MD) + TextNormalizer + Chunker（分块策略对照 wheel 内 pipeline 实现提取）
- `EmbeddingProvider` 接口 + 按 R1 结论的基线实现 + `EmbeddingDescriptor`/embedding_space_id 隔离
- WorkManager 导入管线：分批、进度、取消、进程被杀恢复（`ingest_job` 状态机）
- 周验收：飞行模式导入 100 条文本 → Ready → 可检索（对应 PRD §9.1-1/2/4）

**W2 检索服务与 UI**
- `VectorIndex` 精确扫描实现（按 Spike-4 选型）+ 模型不匹配拒绝检索（§9.1-3/7）
- KeywordRetriever：FTS4 + R3 选定分词方案
- CandidateFusion + 去重 + EvidenceResolver（chunk→document→source 回溯、char_start/end 定位）
- Compose UI 五屏：导入 / 来源列表 / 搜索 / 证据详情 / 设置（模型、维度、隐私开关、离线声明）
- 周验收：Top-K 检索 + 原文定位 + 去重（§9.1-6）；无 LLM 时搜索可用（§9.1-8）

**W3 健壮性、评测与验收**
- 删除级联（source→document→chunk→embedding→FTS 索引，§9.1-5）；模型切换 generation 双缓冲重建（§9.1-7）
- 自动化测试：迁移、索引损坏恢复、磁盘不足、模型文件缺失（§9.1-10）
- 200 条评测集构建（中/英/混合/代码/数字日期；事实查找/同义表达/多跳关联/精确名称/对抗五类），分别报告向量/关键词/融合的 Recall@5/10、MRR@10、NDCG@10
- 三档设备基准报告（§9.2 全指标：延迟、RAM、APK 增量、模型体积、功耗）
- Phase 1 验收清单全项核对 → MVP-1 内部 debug APK 发布
