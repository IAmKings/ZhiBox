# ADR-001：分块策略（无重叠）与跨块答案风险

- **状态**：Accepted（记录现状；Phase 2 评估可选改进）
- **日期**：2026-10-17
- **来源**：P2 计划 B2-6（原审查 core P2-9）
- **决策范围**：TXT/Markdown 文档分块（`core/text/Chunker.kt`），默认 `maxChars=600`、`overlap=0`。

## 背景

当前分块器（`Chunker`）以字符数近似 token，优先在空行/标题边界切块，超长块按 600 字硬切，**块之间无重叠**。RAG 检索命中后只回填单个 chunk 的原文片段（`charStart/charEnd`），若答案句子跨块边界，单块内容可能不完整。

真机检索评测（OneDrive Plus PJZ110/Android 16，v5 schema）当前结果：

- evalset 220 条有标注查询：R@1=0.9636 / R@5=0.9909 / R@10=1.000；
- 分块规模：81 文档 → 83 chunk（平均 ~1 chunk/doc，语料短，跨块问题未被触发）。

## 决策

1. **保持无重叠分块**（overlap=0）作为当前默认：现有评测集（短文档为主）无跨块失败证据；引入重叠会改变 chunk 数量/向量数与去重语义，需要重跑全部评测与重嵌入迁移，成本高于当前收益。
2. **显式记录风险与触发条件**：当语料平均长度显著增加（如长文/教材整章），答案跨块截断风险上升；应在 W5 后以长文档评测集（≥5 个 5k+ 字文档）复测 R@5/R@10，若跨块失败率 >2%，再评估重叠。
3. 若未来引入重叠：
   - `chunk(documentId, ordinal)` 唯一约束**不受影响**（ordinal 仍单调唯一）；
   - chunk 的 `charStart/charEnd` 区间将允许重叠，证据页需渲染相邻块上下文；
   - 必须重新评测（R@1/R@5）并决定是否全量重嵌入（旧 chunk 与新 chunk 文本不同 → 向量需重建）。

## 后果

- 正面：零迁移成本、评测基线稳定、实现简单（无重叠去重/拼接逻辑）。
- 负面：长文档跨块答案可能截断；当前以"检索命中后证据页展示单块 + 相邻块可通过 chunkId/ordinal 扩展"作为缓解，尚未实现相邻块 UI。
- 后续动作：B2-6 仅文档化；实现项记入 Phase 2 backlog（触发条件见上）。
